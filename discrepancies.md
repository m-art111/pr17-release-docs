## 2. Противоречия

| № | Где | Что противоречит | Риск для пользователя | Требуемая правка |
|---|---|---|---|---|
| Р-01 | Руководство ↔ конфигурация и спецификация | Руководство: `max_attachments` 5. Конфигурация и спецификация: 3 | Оператор прикладывает 4–5 файлов, получает отказ и не понимает почему; тратит время, может бросить заявку | В руководстве указать «не более 3 файлов PDF/PNG, до 5 000 000 байт каждый» — [documentation_changes.md](documentation_changes.md), Д-01 |
| Р-02 | Руководство ↔ спецификация | Руководство: «Нажимайте Отправить до появления номера». Спецификация: после тайм-аута сначала проверить список | Повторные нажатия при сохранённой заявке; если текст при повторе изменён — конфликт без новой записи; оператор не понимает, создана ли заявка | Заменить совет порядком «проверить список → один повтор → поддержка» — Д-02 |
| Р-03 | Руководство ↔ кандидат | Руководство версии 1.4.2, кандидат 1.5.0-rc1 | Пользователь получает инструкцию к другой версии | Выпустить фрагмент руководства для 1.5.0 — Д-03 |
| Р-04 | Пакет ↔ спецификация | Спецификация описывает пакет `app-1.5.0`, в пакете — `app-1.5.0-rc1.zip` | Можно перепутать кандидат и итоговую сборку | В паспорте явно указать: проверяется кандидат rc1, а не итоговая сборка |
| Р-05 | Требование R_RESTORE: пакет ↔ спецификация | Пакет: только «RTO ≤ 20 мин и RPO ≤ 15 мин». Спецификация дополнительно требует, чтобы данные после восстановления соответствовали контрольному набору | Восстановление «уложилось по времени», но данные неполные | В матрице проверять оба условия — [traceability.md](traceability.md) |
| Р-06 | Требование R_PERFORMANCE: пакет ↔ спецификация | В пакете нет профиля нагрузки и метода p95. Спецификация: 20 операторов, 1000 заявок, ошибки входят в выборку, p95 — ближайший ранг ceil(0,95·n) | Измерение по другому профилю будет несопоставимо с критерием | В матрице и решении использовать профиль и метод из спецификации |

## 3. Отсутствующие сведения

| № | Чего нет | Последствие |
|---|---|---|
| О-01 | Сам файл `app-1.5.0-rc1.zip` и его хеш | Контроль целостности не подтверждён; имя файла хеш не заменяет |
| О-02 | Настоящий идентификатор коммита: `DEMO-COMMIT-015-NOT-A-REAL-GIT-ID` — учебный маркер | Сборку нельзя связать с исходным кодом |
| О-03 | Доступные журналы: `synthetic-log-E01…E03` — учебные маркеры, не ссылки | Результаты T01–T03 принимаются только как условие кейса; открыть доказательство нельзя |
| О-04 | Результат восстановления: T04 `blocked` (`restore-target-unavailable`), `last_restore_test`: `not_available_in_packet` | R_RESTORE не подтверждён; RTO и RPO не измерены |
| О-05 | Результат производительности: T05 `not_run`, доказательства нет | R_PERFORMANCE не подтверждён |
| О-06 | Время создания резервной копии B-1755 | Нельзя оценить RPO относительно начала работ |
| О-07 | Сведения о целевой среде: ОС, версии Python и PostgreSQL, свободное место | Требования совместимости (Linux x64, Python 3.11/3.12, PostgreSQL 15/16, ≥ 2048 МиБ) не подтверждены |
| О-08 | Состояние журнала миграций (применялась ли M015 ранее) | Повтор миграции допустим только после проверки фактического результата |
| О-09 | Будет ли включена функция `category_required` в этом выпуске | После её включения и появления новых записей возврат на 1.4.2 требует преобразования данных |
| О-10 | Механизм передачи секретов и место подстановки параметров | Указывается как требование, без выдуманных подробностей |
| О-11 | Обновлённое руководство для 1.5.0 | Готовится в этой работе: [documentation_changes.md](documentation_changes.md) |
